一排储物柜

列表在一个名字下按顺序放很多值，写在方括号里。每个位置有编号，叫索引，从 0 开始；-1 是最后一个。

还是这个 tools，tools[2] 是什么？

  1. "list_files"
  2. "edit_file"
  3. "run_bash"
  4. IndexError

索引表示「离开头几步」，第一个离开头 0 步。4 个元素的列表，索引是 0 到 3。

索引从 0 开始，[-1] 是最后一个。

AI 是无状态的：两次请求之间什么都不记得。所以机器人每次都把全部历史再发一遍，请求越来越大：

为什么每次发给 AI 的请求都会变大？

  1. AI 的回答越来越长
  2. 每次都发整个 conversation，而它一直在变长
  3. 后面的消息更贵
  4. Python 列表会越用越重

记忆里只有 10 条，却一共发了 25 条。每多一轮，每次请求就更大一点。

AI 不记事，机器人的记忆就是一个越来越长的列表。

切片取一段

切片 x[start:stop] 取出一段：从 start 开始，到 stop 之前停下。省略 start 就从头开始。

用 --step 3 启动机器人，让它改文件里的错别字，会怎样？

  1. 它把文件改好了
  2. 它连文件夹都看不了
  3. 能读、能列文件，但没有改文件的工具
  4. 它用 shell 命令去改

ALL_TOOLS[:2] 只有前两个工具。同一个 AI，手不一样，能做的事就不一样。

x[:n] 是前 n 个，x[-n:] 是最后 n 个。

编程原则

保留历史，不改写历史

机器人从不删 conversation 里的消息。旧结果太大时，只把内容换成一句简短说明。

多了解一点：两个名字，一个列表

b = a 不会复制列表，只是多贴一个名字。想要独立的副本，用 list(a)。机器人的测试里保存对话快照时，用的就是 list(conversation)。

append 加一个，extend 加一批。

小结

  • 列表按顺序存很多值，len() 数个数。
  • 索引从 0 开始；切片 [start:stop] 在 stop 之前停。
  • append 加一个，extend 加一批。
  • AI 不记事，机器人每次都发送整个 conversation。

关键词

列表 list
方括号里有顺序的一组值。
索引 index
元素的位置，从 0 开始。
切片 slice
取出一段：x[start:stop]。
追加 append
在末尾加一个元素。
无状态 stateless
两次请求之间什么都不记。
副本 copy
独立的新列表：list(a)。
