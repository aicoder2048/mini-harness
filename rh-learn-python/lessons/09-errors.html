读懂报错

报错不是灾难，是 Python 在准确地告诉你哪里出了问题。运行这段带拼写错误的代码：

红框标题告诉你三件事：第几行（第 3 行）、错误类型（NameError）、具体消息（这个名字没定义）。程序到第 3 行就停了，第 4 行没运行。

点开「查看完整的 traceback」：它是一串调用记录，从最下面读起，最后一条就是出错的地方。

一个 traceback 里有四条 File ... line ...。真正抛出错误的是哪一行？

  1. 最上面的第一条
  2. traceback 不会告诉你
  3. 最后一条，就在错误消息的正上方
  4. 行号最大的那一条

Python 打印时「最近的调用排在最后」（most recent call last）。最下面那条就是出错的地方，紧接着是错误类型和消息。

捕获错误

预料得到的错误可以捕获：把可能出错的代码放进 try，出了指定的错就跳到 except，程序接着往下走。运行后把输入改成 12 再试一次。

try 包住可能出错的那几行，except 写明要接住的类型。

失败变消息

这是今天的核心。AI 每要用一次工具，主循环都会调用 _execute：

AI 要用一个叫 rm_rf 的工具，可是根本没有这个工具。机器人会怎么做？

  1. 崩溃，打印 traceback
  2. 把「Error: unknown tool: rm_rf」作为工具结果发回去，让 AI 换个办法
  3. 跳过这次调用，什么都不发回去
  4. 让你重启程序

_execute 抛出 ToolError("unknown tool: rm_rf")，几行后又自己接住，当作错误结果返回。AI 读到后会换个做法。

多了解一点：有些错误就该崩溃

AI 犯的错要接住，让 AI 自己改。程序员犯的错（比如设置写坏了）要立刻停下、说清楚，这叫快速失败。

工具失败不崩溃：变成一条消息交给 AI，让它自己纠正。

别吞掉错误

不写错误类型的 except: 加上 pass，会把所有错误都藏起来，连你自己的拼写错误也一起。看看总价：

总价是 0，却一个报错都没有。把 except: 换成 except ValueError:，拼写错误就会大声报出来。

编程原则

永远别悄悄吞掉错误

只接住你预料到的错误类型；接住之后，要让人看得见：告诉用户、告诉 AI，或者记下来。

except 后面写明类型，别写光秃秃的 except: pass。

动手挑战

挑战

你自己的 _execute

写一个永远不会崩溃的 execute(name, args)，返回一对值（消息保持英文，它们是给 AI 看的）：

  • 正常：("ok", 结果)
  • 没有这个工具：("error", "unknown tool: 名字")
  • 工具抛出 ToolError：("error", 消息)
  • 工具抛出 KeyError：("error", f"missing argument: {e}")
提示

照着 _execute：先 TOOLS.get(name)，在一个 try 里处理 None 和调用，再写 except ToolError 和 except KeyError。

挑战

一个小心谨慎的文本编辑器

写 edit_text(content, old, new)，迷你版 edit_file。先检查坏情况并抛出 ToolError，都没问题才返回替换后的文本：

  • old == new："old_str and new_str must differ"
  • 找不到 old："old_str not found"
  • 出现不止一次："old_str matched 2 times; make it unique"（用真实次数）
提示

先比较 old == new，再用 content.count(old) 数出现了几次。

小结

  • 报错告诉你行号、类型和消息；traceback 从下往上读。
  • try / except 接住预料到的错误；raise 自己抛出。
  • 机器人把工具失败变成给 AI 的消息，从不崩溃。
  • 别写 except: pass，要让错误被看见。
