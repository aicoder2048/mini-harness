为什么要测试

改了一行代码，怎么知道没弄坏？手动问 DeepSeek 又慢又花钱，回答还每次不一样。程序员的办法是写测试：自动运行代码、检查结果的小程序。

# 在终端里，进入项目文件夹
$ uv run pytest -q
........................................................................ [ 34%]
........................................................................ [ 69%]
..............................................................           [100%]
206 passed, 10 deselected in 2.17s

每个点是一个通过的测试：206 项检查，两秒，一分钱不花。每次有人推送代码，GitHub 还会在一台新电脑上自动再跑一遍（这叫 CI）。

测试让电脑替你检查代码，又快又免费。

assert 断言

assert 的意思是「这件事必须成立」。成立就安静地往下走；不成立就抛出 AssertionError，逗号后面的说明会告诉你哪里错了。

运行 assert 2 + 2 == 4 会发生什么？

  1. 打印出 True
  2. 什么都不会发生，程序接着往下走
  3. 程序停下，抛出 AssertionError
  4. 打印出「passed」

通过的断言是安静的。所以才需要 pytest 替你统计：通过的给一个绿点，失败的给一份醒目的报告。

assert 写下「必须成立」的事，不成立就报错。

编程原则

测试是一个一直有效的承诺

每个测试写下代码的一个承诺，以后每次修改都会免费再查一遍。只测从外面看得到的行为，内部重写也不会坏。

测试失败时先问：是代码错了，还是我的预期错了？

假对象

主循环要和 DeepSeek 对话，还要等你打字，怎么测？把这两样都换成假的：FakeProvider 交出写好的回复，scripted() 假装打字。

打个比方

FakeProvider 就像汽车碰撞测试里的假人：形状和真人一样，但便宜、随时都有、永远不会受伤。

测试为什么用 FakeProvider，不用真 DeepSeek？

  1. DeepSeek 在测试里用不了
  2. 为了让测试永远通过
  3. 假对象免费、快、不用联网，每次回复都一样
  4. pytest 不允许联网

真 AI 要钱、要网、要等，说法还每次不同，没法写准确的 assert。假对象把这些问题全解决了。

多了解一点：三行代码的假键盘

用假对象换掉慢的、贵的、会变的东西，测试才稳定。

先写测试

这个项目的规矩是先写测试、再写代码，叫红、绿、重构：先看测试失败（红），写最简单的代码让它通过（绿），再整理代码。

易错点

assert result 只检查结果不是空的，不检查对不对。永远和准确的预期值比较。

还没写代码，新测试就通过了。你该怀疑什么？

  1. 这个测试可能什么都没检查
  2. 代码已经完美了
  3. 没什么好怀疑的
  4. pytest 坏了

从没失败过的测试，可能根本不会失败。「红」这一步就是先证明测试能抓住问题。

先红后绿：先看测试失败，再写代码让它通过。

小结

  • assert 写下必须成立的事；pytest 运行所有 test_ 函数。
  • 每个测试都是：准备、执行、检查。
  • 假对象让测试免费、快速、每次结果一样。
  • 先看测试失败，再让它通过；和准确的值比较。
