消息是字典

机器人记忆里的每条消息都是一个字典：一对对「键 → 值」。就像通讯录：按名字（键）查到号码（值）。

列表用位置 [0] 取值，字典用键的名字 ["role"] 取值。

字典按键查值：d["键"]。

安全地查找

用方括号查一个不存在的键，会报 KeyError。键可能不存在时，改用 .get(键, 默认值)：找不到就给默认值，永远不出错。

最后一行会打印什么？

  1. 报错：KeyError
  2. None
  3. deepseek-v4-flash
  4. sk-123

没有这个键，.get() 就交回你给的默认值。机器人就是这样挑模型的。

元组与解包

元组像列表，但写在 ( ) 里，创建后不能改，适合装一小组固定的东西，比如 ("", "y", "yes")。还可以一行把它拆进几个变量，叫解包：

编程原则

按问题选容器

要顺序用列表，按名字查用字典，固定一小组用元组，问「在不在」用集合。

要反复检查「这个文件夹名该不该跳过」，用哪种容器最合适？

  1. 列表
  2. 字典
  3. 集合
  4. 元组

唯一的问题是「在不在这一组里」，这正是集合的本事，机器人用的就是集合。

集合没有重复，最擅长回答「在不在里面」。

小结

  • 每条消息都是带 "role" 和 "content" 的字典。
  • d["键"] 找不到会报错，d.get("键", 默认值) 不会。
  • 元组是固定组合，能一行解包成几个变量。
  • 集合没有重复，用来回答「在不在里面」。
