读写文件

open() 打开文件，with 保证用完自动关上。这个页面有一块「假磁盘」，写的文件会留到你刷新页面。

模式意思文件已存在时
"r"（默认）读读取它
"w"写先清空再写
"a"追加接在末尾写

用 "w" 模式打开 diary.txt，写了一行。原来的内容会怎样？

  1. 保留下来，新的一行接在末尾
  2. 被清空了，文件里只剩新写的那一行
  3. 文件已存在，Python 报错
  4. Python 会问你要不要覆盖

"w" 一打开就清空，没有提醒也没法撤销。只想接着写，用 "a"。

多了解一点：read_file 为什么要分页

真正的 read_file 每次最多给 AI 500 行。没读完时，它会在末尾写一句给 AI 看的说明，比如 ... (showing lines 1-500 of 1234; call read_file with offset=501 to read more)。AI 看到就会去要下一页。截断了就要说出来，绝不悄悄丢掉内容。

文件可能不存在，也可能根本不是文字（比如图片）。机器人不让这些错误弄崩程序，而是把它们变成发给 AI 的消息：

读文件可能失败，接住错误，把它变成一条消息。

路径与文件夹

路径是文件的地址。input/math.txt 这种相对路径从程序当前所在的文件夹算起。os 模块负责和电脑的文件夹打交道：

写法作用
os.path.join("src", "a.py")拼出路径 src/a.py
os.makedirs(文件夹, exist_ok=True)建文件夹，缺几层建几层
os.walk(文件夹)走遍里面所有文件夹

机器人的 list_files 也这样跳过 .git、.venv 这些没人想读的文件夹。注意要写 dirnames[:] =，os.walk 才会照做。

os.walk 走遍文件夹，dirnames[:] = ... 决定不进哪些。

易错点

真密钥别写进代码、别截图、别传上 GitHub。项目把它放在 .env 文件里，.gitignore 不让 git 保存这个文件。

密钥放环境变量或 .env，永远不进代码和 git。

运行命令

run_bash 能在你的电脑上运行任何终端命令（浏览器里跑不了，这里只看代码）。能力这么大，它有三道保险：

  • 超过 30 秒还没跑完，就强行停掉
  • 输出太长，只留最后 10,000 个字符（报错都在最后）
  • 每条命令执行前，先问你 允许执行? [Y/n/a]

编程原则

最小权限

每个部件只给它干活需要的权力。能动整台电脑的工具，每次都要人来批准。

机器人的哪个工具每次使用前都要问你？

  1. read_file
  2. list_files
  3. edit_file
  4. run_bash

只有 run_bash 写着 needs_approval=True。回答 a，这次会话里就不再问了。

危险的事让人来批准：run_bash 每条命令都先问你。

小结

  • with open(...) 读写文件；"w" 会清空，"a" 是追加。
  • 读文件出错时接住它，变成一条消息，不让程序崩溃。
  • os.path.join 拼路径，os.walk 走遍文件夹。
  • 密钥放环境变量；run_bash 每条命令都先问人。
