读懂主循环

你学过的每个零件，都汇进了 src/agent.py 的 Agent.run。它就是机器人的心跳，下面是原文。

行做什么
191–196准备：空的对话记录，两个控制变量
197–218轮到你时：读输入、认命令、把消息加进记录
221把整个对话记录发给模型

237–248没工具调用 → 轮到你；有 → 记一轮，到上限就刹车，否则直接再问模型

工具跑完后，第 248 行把 need_user_input 设成 False。为什么不先问你？

  1. 为了省 token 的钱
  2. 模型要工具是因为需要结果，只有它知道拿到结果后该做什么
  3. Python 不能连续调用两次 input()
  4. 这样程序跑得更快

模型说「请读 input/math.txt」，是因为它想看文件。模型和工具你来我往、不用你插手，这就是 agent 和聊天机器人的区别。

错误变结果

第 235 行对每个工具调用执行一次 _execute。它的每条路都以 return 结尾，失败也会变成一个错误结果。

易错点

每个工具调用都必须有且只有一个回复。少回一个，下一次请求就会被 DeepSeek 拒绝，会话直接卡死。

如果 _execute 里没有 try/except，模型又要读一个不存在的文件，会怎样？

  1. 模型收到错误消息，换个办法
  2. 程序崩溃，对话记录（机器人的记忆）全部丢失
  3. Python 自动跳过这个调用
  4. 创建一个空文件

异常一路往上冲出 run，程序停下，只存在内存里的 conversation 也没了。变成错误结果，模型就能读到问题、换个计划。

工具失败不崩溃，而是变成错误结果交给模型。

终端

Chat with DeepSeek — 4 个工具可用（/exit、/quit 或 Ctrl-D 退出）

模拟器里，模型每次都收到整个对话记录。为什么？

  1. 模型在两次请求之间什么都不记得，这个列表就是唯一的记忆
  2. 为了让模型写出更长的回答
  3. 为了少用一些 token
  4. 为了让服务器检查密码

模型是无状态的，每次请求都从零开始。所以真机器人要统计 token、修剪旧结果：这个列表只会越来越长。

模型不记事，每次都要把整个对话记录重新发过去。

编程原则

循环要小，零件要聪明

主循环只管轮到谁、把对话记录传下去。难办的事都藏在函数和类里，所以换个大脑不用改循环一行。

小结

  • 整个机器人都在 Agent.run 的一个 while True 里运行。
  • need_user_input 决定轮到你，还是轮到模型。
  • _execute 把失败变成错误结果；刹车拦住失控的循环。
  • 你亲手搭了一个 agent。下一课：不花钱也能证明它没坏。
