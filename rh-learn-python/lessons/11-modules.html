打个比方

模块像架子上的工具箱。import math 是把箱子拿下来，math.sqrt 里的点号就是伸手进箱子拿工具。

agent.py 里写着 from tools import read_file。之后它怎么用这个工具？

  1. tools.read_file
  2. read_file
  3. import.read_file
  4. tools(read_file)

from ... import 把名字直接拿进当前文件，所以直接写 read_file。

import x 用 x.名字；from x import 名字 直接用名字。

多了解一点：两个导入陷阱

别用模块名给自己的文件起名：Python 先在你的文件夹里找，你的 statistics.py 会挡住真正的模块。也别写 from x import *，它会悄悄覆盖同名的东西。

一个文件只干一件事，导入只朝一个方向。

装别人的包

包是别人发布出来给大家用的模块。机器人用了三个：openai（和 DeepSeek 对话）、rich（漂亮地显示回答）、prompt_toolkit（高级输入行）。它们写在 pyproject.toml 里：

uv 读这个清单，把包装进项目自己的 .venv 文件夹：

# 在终端里，进入项目文件夹之后：
uv sync              # 安装清单里的所有包
uv add requests      # 加一个新包，并写进清单
uv run src/agent.py  # 在装好包的环境里运行

这个页面里的 Python 只有标准库，所以 import openai 在这里会报错。

包写进 pyproject.toml，用 uv 安装和运行。

robot.py 里有一行 print(__name__)。另一个文件运行了 import robot。会打印什么？

  1. __main__
  2. robot
  3. robot.py
  4. 什么都不打印

被导入的模块，__name__ 就是它的模块名。

多了解一点：JSON，程序之间的通用语

AI 想用工具时，参数是用 JSON 格式的文字发来的。标准库的 json 模块负责翻译：json.dumps 把字典变成文字，json.loads 把文字变回字典。

if __name__ == "__main__": 后面的代码，只在直接运行时才执行。

小结

  • import x、from x import y、import x as z 三种写法。
  • 每个 .py 文件都是模块；机器人的文件只朝一个方向导入。
  • 包写进 pyproject.toml，用 uv sync 安装。
  • if __name__ == "__main__": 只在直接运行时启动程序。
