同一个大脑

在《拆机学 Python》第 00 课我们说过：Agent = 模型 + harness。模型只会「文字进、文字出」，其余的事都是 harness 在做。

今天做一个实验：模型一点不换，只换 harness 的配置，看看能不能得到三个完全不同的 agent。

角色（切换用的名字）工具它的活儿
🧘 唐僧 tang读、列、改（3 个）策划：问清楚你想做什么，写成 PLAN.md，不写代码
🐒 孙悟空 wukong读、列、改、跑（4 个）程序员：照着 PLAN.md 写代码、跑代码
🐷 猪八戒 bajie读、列（2 个）检查员：对照 PLAN.md 挑毛病，只看不改

打个比方

同一个演员，换一份剧本（提示词）、换一套道具（工具）、换一本记事本（对话记录），就演成了另一个人。演员本人（模型）从头到尾没换过。

西游记的设定正好对得上：悟空本领最大，可每次动手都得先听师父的；唐僧不会打架，只管定方向；八戒眼尖嘴碎，挑毛病最在行。悟空头上的紧箍咒，就是 harness 里的规矩和审批：本领再大，也要守规矩。

从悟空切换到八戒，下面哪一样没有换？

  1. 系统提示词
  2. 可用工具
  3. 对话记录
  4. 模型（DeepSeek）

三个角色背后是同一个 DeepSeek。变的全是 harness 那一边。

换角色 = 换 harness 的配置；模型不换。

模型每次读到什么

你每说一句话，harness 就给模型寄一个「包裹」。模型看不见你的电脑，也不记得上一次，它知道的一切都在这个包裹里，而包裹里装的全是文字：

所以 harness 做的很多事，最后都落到同一个地方：往包裹里放什么文字。切换角色，就是换掉 ①，换掉 ② 里的工具，换一份 ③。

Harness 原则

提示词是 Agentic Engineering 的原子单位

模型只读文字。想让 agent 换个身份、多一条规矩、少一种能力，最终都要变成提示词里的一段文字。会看、会写、会装配提示词，是搭 agent 的基本功。

你一句话都没说，八戒就知道自己叫八戒、只能看不能改。他是从哪儿知道的？

  1. DeepSeek 自己记得
  2. 悟空告诉他的
  3. 每次请求的包裹里，第一段就是八戒的系统提示词
  4. 他自己去电脑上查了

系统提示词每次都在包裹的最前面。模型「是谁」，全看这段文字写了什么。

模型知道的一切，都在每次请求的包裹里；包裹里全是文字。

把规律整理成表：

段落谁写的什么时候出现
角色正文我们（角色文件的正文）总是在最前面
Working directoryharness总是：启动时填当前文件夹
# Agencyharness总是：列出可用工具，要求「真去做，别只说」。工具越多，这段的规矩越多：有 edit_file 就加「先读后改」，有 run_bash 就加「被拒绝了别重试」

# Memoryharness有记忆目录、又能改文件：教它怎么记笔记

Harness 原则

提示词写「策略」，能力交给工具

提示词讲该怎么做、有什么界限；能做什么，由工具说了算。所以 harness 让提示词跟着工具变：没有手就不谈「改动要小」，没法运行就不谈「改完要验证」。

在装配台里给八戒打开 run_bash，多出了 Guardrails 和 Verification 两段。为什么一开始没有 Verification（「改完要运行验证」）？

  1. 因为他叫八戒
  2. 他没有 run_bash，没法运行程序，要求他验证没有意义
  3. 写提示词的人忘了加
  4. 提示词太长，删掉了

提示词不该要求角色做它做不到的事。规矩跟着能力走。

系统提示词 = 我们写的角色正文 + harness 按配置自动装配的段落。

写好角色提示词

蓝色那段是我们写的，也是最值得花心思的地方。这是八戒角色文件的正文（也就是上一节蓝色那段）：

三个角色的文件都是同一个结构。读完再看下面的表：每一招都能在原文里找到。

招数为什么有用八戒原文里的例子
① 身份和团队模型知道自己是谁、和谁配合「你是猪八戒……猴哥写代码，师父写计划」
② 一句话任务目标清楚，不跑题「对照 PLAN.md，检查悟空写的代码」
③ 分步骤复杂的活儿拆成小步，不漏步「1. 先读 PLAN.md……2. 一条一条检查」
④ 说清楚输出长什么样结果整齐、好用、能比较「每条写成一行：✅ 做到了 / ❌ 没做到」
⑤ 写明做不到的事不假装、不硬来「你没有改文件的工具」「结论都是读代码看出来的」
⑥ 排好优先级两件事冲突时知道听哪个「规矩（比搞笑更重要）」
⑦ 交接知道活儿干完交给谁「告诉用户：输入 /persona wukong……」
⑧ 语气放最后有个性，但不抢正事「好笑的话只放在开头或结尾，别混进清单里」

这八招可以归进四个固定的段。专业的 agent 提示词常用这个结构，换一个领域也一样用：

段管什么对应的招数八戒原文
目的 Purpose你是谁、要干什么① ②开头两段
步骤 Workflow先做什么、后做什么③「怎么做」1–4
规矩 Instructions边界和优先级⑤ ⑥「规矩（比搞笑更重要）」
汇报 Report结果长什么样、交给谁④ ⑦✅ / ❌ 清单，「交给猴哥」

悟空的第一步还多了一招守卫：「先读 PLAN.md。如果没有 PLAN.md，先问用户要做什么」。缺了必需的东西就先停下来问，而且放在最前面，免得干到一半才发现白干。

多了解一点：提示词的 1–4 级

把提示词按「用到的最高能力」分级，每升一级多一种能力：

级多了什么能力本课的例子
1 · 一段话存起来，反复用「你是检查员，帮我看看代码。」
2 · 工作流有任务、有步骤、有汇报格式八戒
3 · 控制流会判断（「如果……就……」）、会循环悟空：「如果没有 PLAN.md，先问用户」
4 · 委派把活儿派给别的 agent后面的课：软件工厂

原则：能用低一级解决的，就别写高一级。级别越高，能出错的地方越多。

对比一个「差」的版本：

差的提示词缺了什么
「你是检查员，帮我看看代码。」看哪些代码？对照什么检查？结果写成什么样？看完交给谁？不确定时怎么办？模型只好自己猜。

八戒的提示词里写了「宁可说『不确定』，也不要瞎编」。这主要用的是哪一招？

  1. ⑤ 写明做不到的事：他没法运行程序，不能假装确定
  2. ③ 分步骤
  3. ⑦ 交接
  4. ⑧ 语气

模型很愿意「给个答案」。明确允许它说不确定，它才不会为了好看编一个。

好的角色提示词：身份、任务、步骤、输出格式、边界、优先级、交接，最后才是语气。

Harness 原则

围墙比劝告可靠

想让八戒不改代码，可以在提示词里写「别改」，那是劝告，模型可能不听。更可靠的是包裹里根本没有 edit_file 的说明书，harness 也不替他执行，这是围墙。只给干活需要的工具，叫最小权限。

再看 ③：对话记录每一轮都整份重寄。每个角色各有一份，切换角色就换一份。切换时 harness 会告诉你换掉了什么：

你对唐僧说「我喜欢太空游戏」，然后切到悟空问「我喜欢什么？」。悟空会怎样？

  1. 知道，因为是同一个 DeepSeek
  2. 不知道：他的包裹里没有这句话
  3. 会去问唐僧
  4. 程序报错

「记得」只是因为 harness 把对话记录放进了包裹。悟空的包裹里是悟空自己的那份。

多了解一点：为什么不让三个角色共用一份对话？

一是分不清自己是谁：一份对话里一会儿唐僧一会儿八戒，模型容易串戏。二是省钱：DeepSeek 会缓存包裹开头那一段，开头不变，下次就便宜。每个角色各用一份对话，开头（它的系统提示词）一直不变，缓存就一直有效。终端里每次请求后那行灰字的 cached，就是缓存命中的 token 数。

工具说明书和对话记录也是提示词；角色换了，它们跟着换。

动态加载与修剪

包裹不是一成不变的。harness 会按情况往里加东西，也会在太长时往外拿东西：

什么怎么进包裹为什么这样做
项目说明 AGENTS.md工作目录里有这个文件，启动时整份加进系统提示词（最多 2 万字符）项目自己的命令、约定、踩过的坑，每个角色都该知道
记忆笔记只放一张目录：每篇笔记一行标题；正文要用时再读十几篇笔记全文放进去，还没干活就占满了。agent 自己记下的经验，下次就成了它的提示词：越用越在行
技能（skill）也只放目录：每个技能一行说明；用到才读它的 SKILL.md同上：先知道「有什么」，用时再看「怎么做」
换角色 / /persona reload整份系统提示词换掉；reload 时对话保留改了角色文件，马上就能看到效果
修剪旧的工具结果包裹超过 6 万 token 时，把最近 5 个之外的工具结果换成一句「已省略」读过的长文件越积越多，会挤爆包裹

「先放目录，用时再读全文」有个名字，叫渐进式披露：包裹里放最少但够用的东西。

易错点

修剪不是每轮都做，而是超过预算时才一次性做。因为包裹开头一变，缓存就失效了：天天修剪，反而更贵。

记忆为什么只把笔记的标题放进系统提示词？

  1. 正文是秘密，不能给模型看
  2. 模型读不懂正文
  3. 包裹的空间有限：先告诉它有什么，用到哪篇再读哪篇
  4. 标题是英文的

包裹越大越贵，模型也越容易分心。渐进式披露让每样东西在需要时才进来。上下文怎么管，是这个系列后面的课。

harness 动态决定往包裹里放什么、什么时候拿走：这就是上下文管理的起点。

自定义一个角色

三个角色都是 .agents/personas/ 里的文字文件。想要一个新角色，不用改程序，写一个新文件就行：

配置管什么
name切换时打的名字：/persona bajie。小写字母、数字、连字符
title、emoji终端里显示的名字和图标
description/persona 列表里的一句话介绍
tools包裹里放哪几份工具说明书，harness 替它执行哪几种工具。写在一行，逗号隔开；不写就是纯聊天

和角色有关的命令都只在终端显示，不进包裹，也不花钱：

命令作用
/persona列出所有角色，→ 是当前的
/persona 名字切换，并打印换掉了什么
/persona reload改完当前角色的文件后重新读，对话保留；文件改坏了就继续用原来的
/prompt当前角色完整的系统提示词
/tools当前角色的工具；/tools 名字 看那份工具说明书
/status一屏看：角色、模型、工具、提示词长度、对话条数、记忆

易错点

新建的角色文件要重启程序才会被发现；/persona reload 只重新读当前角色。tools 写错了名字（比如 read_files），启动时会提醒，并跳过这个角色。

  4. 换一个更大的模型

进阶：要是提示词和工具「打架」呢？

在 bajie.md 的 tools: 里加上 edit_file，正文一个字不改（正文还写着「你没有改文件的工具」），然后 /persona reload，再让他改一次。

观察：他是听提示词的「我没有手」，还是用了新到手的工具？用 /prompt 看看，Available tools 那一行和正文是不是说法矛盾了。做完记得把 tools: 改回去，再 /persona reload。

结论：提示词和配置要说一样的话。改了工具，就要检查正文里有没有过时的说法。

禁止某件事，最可靠的办法是不给工具；改了工具，记得同步提示词。

实验四：接力

把三个角色串成一支小队，修好 game.py。你是项目经理，负责在他们之间传话：

  1. 唐僧：说「我想把 game.py 改成一个能玩的猜数字游戏」，回答他的问题，直到他写好 PLAN.md。
  2. 悟空：说「照着 PLAN.md 修好 game.py」。他每次要运行命令，先看清楚再回答 y。
  3. 八戒：说「对照 PLAN.md 检查 game.py」，拿到一张 ✅ / ❌ 清单。
  4. 有 ❌ 的话，切回悟空，把八戒的清单告诉他，让他接着改。

做完后打开 PLAN.md 读一读。这场接力里，藏着三种更高级的提示词用法：

用法在接力里要记住的
模板：用提示词生成提示词唐僧的提示词规定了 PLAN.md 的格式（目标 / 功能清单 / 怎样算做完）。他写出来的 PLAN.md，就是给悟空的提示词模板定好骨架，每次只填内容；模板写错，产出全错
把提示词当参数悟空的做法固定（读计划、一步步改、运行验证），PLAN.md 每次不同外层做法写一次，内层任务随便换
指令还是数据悟空把 PLAN.md 当指令去执行；八戒把 game.py 当数据检查，不执行它读进来的文件是要「照做」还是只「看看」，提示词里要说清楚

还有一个好处：人可以插在中间。悟空动手之前，你可以先打开 PLAN.md 改一改，他就会照着改过的计划做。最后对每个角色 /status，比比谁的对话最长。

多了解一点：能不能不用我传话？

能。让 harness 自己把八戒的清单交给悟空、让悟空改完自动叫八戒再查，就是更进一步的「软件工厂」：几个 agent 按流程接力，人只在关键处把关。那是这个系列后面的课。

agent 之间靠文件交接；交接的文件，就是下一个 agent 的提示词。

小结

  • Agent = 模型 + harness。换角色只换 harness 的配置，模型不换。
  • 模型知道的一切都在每次请求的包裹里：系统提示词、工具说明书、对话记录，全是文字。
  • 系统提示词是装配出来的：我们写的角色正文 + harness 按配置加的段落。
  • 好的角色提示词：身份、任务、步骤、输出格式、边界、优先级、交接，最后才是语气。
  • 不给工具比在提示词里说「别做」更可靠；改了工具，记得同步提示词。
  • harness 动态往包裹里加东西、也会修剪：先放目录，用时再读全文。
  • 文件是 agent 之间的接口：PLAN.md 是唐僧写给悟空的提示词；读进来的文件是指令还是数据，要说清楚。

关键词

系统提示词 system prompt
每次请求放在最前面的说明：你是谁、守什么规矩。
装配 prompt assembly
harness 按配置把几段文字拼成一份提示词。
角色 persona
一套配置：角色正文、工具、自己的对话和记忆。
工具说明书 tool description
告诉模型某个工具干什么、怎么用的一段文字。
最小权限 least privilege
只给干活需要的工具。
渐进式披露 progressive disclosure
先放目录，用到时再放全文。
工作流提示词 workflow prompt
目的、步骤、规矩、汇报四段齐全的提示词。
模板 template
固定骨架、留出空位，让 agent 照着填出一份新提示词。
交接 handoff
一个 agent 把成果（通常是文件）交给下一个。

提示词分级、工作流四段、模板和「把提示词当参数」的说法，参考了 IndyDevDan《Tactical Agentic Coding》的 Agentic Prompt Engineering 一课。
