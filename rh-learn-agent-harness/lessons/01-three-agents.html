同一个大脑

在《拆机学 Python》第 00 课我们说过：Agent = 模型 + harness。模型只会「文字进、文字出」，其余的事都是 harness 在做。

今天做一个实验：模型一点不换，只换 harness 的配置，看看能不能得到三个完全不同的 agent。

角色（切换用的名字）工具它的活儿
🧘 唐僧 tang读、列、改（3 个）策划：问清楚你想做什么，写成 PLAN.md，不写代码
🐒 孙悟空 wukong读、列、改、跑（4 个）程序员：照着 PLAN.md 写代码、跑代码
🐷 猪八戒 bajie读、列（2 个）检查员：对照 PLAN.md 挑毛病，只看不改

打个比方

同一个演员，换一份剧本（系统提示词）、换一套道具（可用工具）、换一本记事本（会话状态），就演成了另一个人。演员本人（模型）从头到尾没换过。

西游记的设定正好对得上：悟空本领最大，可每次动手都得先听师父的；唐僧不会打架，只管定方向；八戒眼尖嘴碎，挑毛病最在行。悟空头上的紧箍咒，就是 harness 里的规矩和审批：本领再大，也要守规矩。

从悟空切换到八戒，下面哪一样没有换？

  1. 系统提示词
  2. 可用工具
  3. 对话记录
  4. 模型（DeepSeek）

三个角色背后是同一个 DeepSeek。变的全是 harness 那一边。

换角色 = 换 harness 的配置；模型不换。

八戒的提示词里为什么没有 # Verification（「改完要运行验证」）？

  1. 因为他叫八戒
  2. 他没有 run_bash，没法运行程序，要求他验证没有意义

提示词不让角色做它做不到的事：没有手就不谈改，没法运行就不谈验证。

Harness 原则

提示词写「策略」，能力交给工具

提示词讲的是该怎么做、有什么界限；能做什么，由工具说了算。所以提示词要跟着工具变。

系统提示词 = 我们写的角色正文 + harness 按工具自动加的段落。

组件二：可用工具

工具是 agent 的手。角色文件里 tools: 那一行，决定了它有哪几只手。harness 只把这几个工具的说明发给模型：

输入 /tools 看当前角色的工具；/tools 名字 看发给模型的英文说明：

那行中文说明只给人看，不会发给模型。模型看到的是英文的说明和参数表。

Harness 原则

围墙比劝告可靠

想让八戒不改代码，可以在提示词里写「别改」，那是劝告，模型可能不听。更可靠的是根本不给他 edit_file，这是围墙：模型就算想改，harness 也没有这只手借给它。这就是最小权限：只给干活需要的工具。

你想让唐僧也能运行命令。最直接的做法是？

  1. 在唐僧的提示词里加一句「你可以运行命令」
  2. 换一个更聪明的模型
  3. 在 tang.md 的 tools: 一行加上 run_bash，然后 /persona reload
  4. 先切到悟空，再切回唐僧

能不能做，看工具。改完角色文件，用 /persona reload 重新读一遍，不用重启程序。

可用工具决定 agent 能做什么；不给工具，比在提示词里说「别做」更可靠。

挑战

读懂 tools: 那一行

角色文件里写的是一行文字，比如 tools: run_bash ,read_file。写一个函数 pick_tools(line)，把它变成工具名的列表：

  • 去掉空格；什么都没写，就返回空列表（纯聊天，一个工具都没有）。
  • 按 ALL_TOOLS 的顺序排，重复的只留一个："run_bash ,read_file" → ["read_file", "run_bash"]。
  • 遇到不认识的工具，raise ValueError，消息里写出它的名字。
提示

先用 line.split(",") 切开，每段 .strip() 去掉空格；再检查每个名字在不在 ALL_TOOLS 里；最后照着上面第 565 行的推导式，从 ALL_TOOLS 里挑。

配置是文字，harness 要先把它读成程序能用的数据，读不懂就明确报错。

你对唐僧说「我喜欢太空游戏」，然后切到悟空问「我喜欢什么？」。悟空会怎样？

  1. 知道，因为是同一个 DeepSeek
  2. 不知道：他自己的对话记录里没有这句话
  3. 会去问唐僧
  4. 程序报错

模型本身什么都不记得，「记得」全靠 harness 把对话记录发过去。悟空收到的是悟空自己的那份。

多了解一点：为什么不让三个角色共用一份对话？

一是分不清自己是谁：一份对话里一会儿唐僧一会儿八戒，模型容易串戏。二是省钱：DeepSeek 会缓存每次请求开头那一段，开头不变，下次就便宜。每个角色各用一份对话，开头（它的提示词）一直不变，缓存就一直有效。终端里每次请求后那行灰字的 cached，就是缓存命中的 token 数。

会话状态（对话、记忆、审批）每个角色一份；切换角色，换的是整份状态。

命令作用

/persona 名字切换，并打印换掉了什么

易错点

tools: 只能写成一行，用逗号隔开。写错了工具名（比如 read_files），程序启动时会提醒你，并跳过这个角色。

角色就是一个文字文件：配置写在上面，提示词写在下面。

易错点

和角色说话会调用 DeepSeek，按用量收费（很便宜，但会花钱）；斜杠命令不花钱。悟空每次运行命令都会问 允许执行? [Y/n/a]，先看清楚命令再回答。

给老师：三个毛病是什么
  1. input() 得到的是文字，直接和数字比大小会报 TypeError，要先 int(guess)。
  2. 猜对了没有 break，循环停不下来。
  3. 提示说「1 到 100」，randint(1, 10) 却只出 1 到 10。

实验在练习文件夹里做，三个角色和你的文件都在这里。

实验一：同一句话

对三个角色说一模一样的一句话：「帮我把 game.py 修好」。

  1. /persona tang，然后说：帮我把 game.py 修好
  2. /persona wukong，再说一遍
  3. /persona bajie，再说一遍

把看到的填进表里（每次说法会不一样，看的是它做了什么）：

角色它做了什么？用了哪些工具？（看绿色的 tool: 行）
🧘 唐僧　　
🐒 孙悟空　　
🐷 猪八戒　　

大概会看到：唐僧先追问你想要什么，打算写计划；悟空读代码、改代码，还会请你同意运行它；八戒读完代码列出问题，但告诉你他没有手，改不了。

想一想

同一句话，三个反应。用 /tools 和 /prompt 找找原因：分别是哪个组件让它们不一样？

同一个模型，不同的 harness，就是不同的 agent。

实验二：记忆隔离

  1. /persona tang，说：我喜欢太空游戏
  2. /persona wukong，问：我喜欢什么游戏？
  3. /persona tang，再问一次同样的问题
  4. 每一步之后都输入 /status，看「对话」那一行的数字

悟空答不上来，唐僧答得上来。/status 里两个角色的对话条数各算各的。

想让悟空也知道你喜欢太空游戏，下面哪个办法行得通？

  1. 切到悟空，直接告诉他；或者让唐僧把它写进 PLAN.md，悟空去读
  2. 多切换几次，让他们「熟」一点
  3. 重启程序
  4. 换一个更大的模型

角色之间不共享对话。要传话，要么你自己说，要么通过文件：工作目录里的文件是大家共用的。

对话记录各管各的；要交接，就写进文件。

实验三：围墙

  1. /persona bajie
  2. 说：别光说，直接帮我把 game.py 改好！
  3. 再输入 /tools，数一数他有几个工具

八戒怎么劝都改不了：他的工具里没有 edit_file，harness 没把这只手给他。他大概会说「俺老猪只有眼睛没有手」。

想一想

八戒的提示词里也写了「你没有改文件的工具」。如果只写这句话、却把 edit_file 给了他，会怎样？哪一个更靠得住：提示词里的话，还是工具清单？

禁止某件事，最可靠的办法是不给工具。

实验四：接力

把三个角色串成一支小队，修好 game.py。你是项目经理，负责在他们之间传话：

  1. 唐僧：说「我想把 game.py 改成一个能玩的猜数字游戏」，回答他的问题，直到他写好 PLAN.md。
  2. 悟空：说「照着 PLAN.md 修好 game.py」。他每次要运行命令，先看清楚再回答 y。
  3. 八戒：说「对照 PLAN.md 检查 game.py」，拿到一张 ✅ / ❌ 清单。
  4. 有 ❌ 的话，切回悟空，把八戒的清单告诉他，让他接着改。

做完后，在 xiyou 里看看多了哪些文件，再对每个角色 /status，比比谁的对话最长。

多了解一点：能不能不用我传话？

能。让 harness 自己把八戒的清单交给悟空、让悟空改完自动叫八戒再查，就是更进一步的「软件工厂」：几个 agent 按流程接力，人只在关键处把关。那是这个系列后面的课。

agent 之间靠文件交接；现在，你就是把它们串起来的那个流程。

小结

  • Agent = 模型 + harness。换角色只换 harness 的配置，模型不换。
  • 系统提示词 = 我们写的角色正文 + harness 按工具自动加的段落。
  • 可用工具决定 agent 能做什么；不给工具，比在提示词里说「别做」更可靠。
  • 会话状态（对话、记忆、审批）每个角色一份；角色之间靠文件交接。
  • 角色写在 .agents/personas/名字.md；/persona、/prompt、/tools、/status 随时看。
